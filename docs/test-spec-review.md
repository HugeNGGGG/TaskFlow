# 测试提示词与当前实现差异审查

## 总体判断

这份测试提示词覆盖很全面，大部分功能测试、集成测试、边界测试和安全测试都能直接映射到当前项目。

但有几条测试期望与当前实现不完全一致，直接拿去跑会失败。

## 需要修复的实现缺口

### 1. F-16 子任务删除

- 测试要求：可以删除子任务。
- 当前实现：子任务只有新增、列表、更新完成状态，没有删除接口。
- 影响：删除相关测试会失败。

### 2. F-17 任务模板编辑、删除、默认子任务

- 测试要求：模板可编辑/删除，可包含默认子任务。
- 当前实现：模板只有创建和列表，创建任务时能带入基础字段；没有编辑、删除、默认子任务。
- 影响：模板管理相关测试会失败。

### 3. F-25 打卡时间范围校验

- 测试要求：非打卡时间、过早/过晚打卡应被处理。
- 当前实现：后端只防重复打卡，没有实现“不得早于 1 小时 / 晚于 5 分钟”的时间范围校验。
- 影响：异常时间打卡测试不通过。

### 4. F-26 加班、标准工时、考勤工时规则

- 测试要求：跨日、加班、缺卡、标准工时等规则。
- 当前实现：能配对上下班并计算基础工时，但没有完整区分标准工时、加班、出勤异常口径。
- 影响：复杂工时规则测试可能失败。

### 5. F-27 补卡通过后回写打卡记录

- 测试要求：审批通过后修正打卡记录。
- 当前实现：审批通过只更新补卡状态并重算会话，没有直接新增/修改 `PunchRecord`。
- 影响：补卡后的打卡流水和原始记录对不上。

### 6. F-28 请假通过后与考勤/工时联动

- 测试要求：请假通过后正确影响考勤和工时。
- 当前实现：请假状态可以审批，但考勤看板和工时统计尚未把请假完整纳入计算。
- 影响：请假与考勤统计联动测试可能失败。

## 与当前实现一致的测试

以下测试方向已经具备对应能力，可以放心生成测试提示词：

- Web 登录、刷新轮换、登出
- 微信登录与绑定
- 用户、部门、类别管理
- 任务发布、接取、进度、提交、审核、取消、延期
- 附件上传、版本、下载、打包
- 评论与 @提醒
- 排行榜、个人战绩、员工统计
- 站内通知、公告
- 任务 CSV 导出、全局搜索
- 考勤打卡、考勤记录、考勤看板与导出
- 大屏展示与手动刷新

## 建议

如果这套测试要作为正式验收，建议先补齐上面 6 个实现缺口，尤其是：

1. 子任务删除
2. 任务模板编辑/删除
3. 打卡时间范围校验
4. 补卡通过回写打卡记录
5. 请假与考勤统计联动
6. 标准工时/加班计算

否则需要先修改测试提示词，把未实现的验收点标记为“待实现”或降级为当前 MVP 范围。
